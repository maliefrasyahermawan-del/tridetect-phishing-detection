BAGIAN 1 — APA ITU TRIDETECT?
================================================================================

Tridetect adalah sistem deteksi phishing komprehensif yang dirancang untuk
melindungi pengguna Indonesia dari TIGA jenis serangan phishing modern:

  1. WEB PHISHING   → URL / website palsu yang meniru brand legitimate
                      Contoh: "http://g0pay-verify.tk/login" berpura-pura jadi GoPay

  2. SMISHING       → Phishing melalui SMS / WhatsApp
                      Contoh: "AKUN BCA ANDA DIBEKUKAN, klik: bit.ly/xxx"

  3. VISHING        → Phishing melalui telepon / voice call (Phase 2)
                      Contoh: penipu mengaku dari bank minta kode OTP

TUJUAN UTAMA:
  - Deteksi otomatis URL berbahaya sebelum user klik
  - Klasifikasi SMS phishing Indonesia dengan NLP berbahasa Indonesia
  - Proteksi multi-layer terhadap pencurian identitas digital
  - Dashboard monitoring untuk tim SOC / keamanan siber

BAGIAN 2 — FUNGSI SETIAP MODULE

┌─────────────────────────────────────────────────────────────────────────────┐
│ MODULE 1: WEB PHISHING DETECTOR                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│ File Utama: tridetect/modules/web_phishing/                                 │
│                                                                             │
│ FUNGSI:                                                                     │
│   Menganalisis URL/link apakah berbahaya berdasarkan 3 lapisan:             │
│                                                                             │
│   A. Lexical Feature Extraction (features.py)                               │
│      - Ekstrak 25+ fitur dari URL:                                          │
│        * Panjang URL (URL sangat panjang → mencurigakan)                    │
│        * Penggunaan IP address (http://192.168.1.1/login → phishing)        │
│        * TLD mencurigakan (.tk .ml .ga .cf .xyz → sering disalahgunakan)    │
│        * URL shortener (bit.ly, tinyurl → menyembunyikan tujuan asli)       │
│        * Tanda @ di URL (menipu browser)                                    │
│        * Encoding hex (%61%62 → obfuskasi)                                  │
│        * Subdomain berlebihan (a.b.c.bank.tk → impersonasi)                 │
│        * Kata brand di URL (login, secure, verify, bca, gopay, dll)         │
│                                                                             │
│   B. Brand Typosquat Detection (brand_detector.py)                          │
│      - Bandingkan domain dengan 33 brand Indonesia & global                 │
│      - Gunakan algoritma Levenshtein Distance (ukur kesamaan teks)          │
│      - Threshold: edit distance ≤ 2 = TYPOSQUAT                             │
│        Contoh: "g0pay" vs "gopay" → distance 1 → TYPOSQUAT GoPay           │
│        Contoh: "bcaa" vs "bca" → distance 1 → TYPOSQUAT BCA                │
│      - Database brand: BCA, Mandiri, BNI, BRI, GoPay, OVO, Dana,           │
│        Shopee, Tokopedia, Lazada, Telkomsel, PLN, dll (33 brand)            │
│                                                                             │
│   C. SSL Certificate Check (ssl_checker.py)                                 │
│      - Cek validitas sertifikat HTTPS                                       │
│      - Deteksi: sertifikat sangat baru (< 30 hari → phishing baru dibuat)   │
│      - Deteksi: sertifikat kadaluarsa                                       │
│      - Deteksi: issuer tidak dikenal                                        │
│      - Timeout: 3 detik (tidak memblock request)                            │
│                                                                             │
│   FORMULA SKOR (Weighted Aggregate):                                        │
│     Score = (Classifier × 0.50) + (Brand × 0.30) + (SSL × 0.20)           │
│     ≥ 0.55 → MALICIOUS | 0.28–0.54 → SUSPICIOUS | < 0.28 → SAFE           │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ MODULE 2: SMISHING DETECTOR                                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│ File Utama: tridetect/modules/smishing/                                     │
│                                                                             │
│ FUNGSI:                                                                     │
│   Menganalisis teks SMS/WhatsApp apakah mengandung phishing.                │
│                                                                             │
│   A. Text Preprocessing (preprocessor.py)                                  │
│      - Normalisasi slang Indonesia (gw→saya, lo→kamu, gak→tidak, dll)      │
│      - Ekstraksi URL dari teks SMS                                          │
│      - Ekstraksi nominal uang (Rp 50.000.000, dst)                          │
│      - Deteksi ALL CAPS ratio (> 30% huruf kapital → signal urgensi)        │
│      - Deteksi bahasa (Indonesia / English / campuran)                      │
│                                                                             │
│   B. IndoBERT NLP Classifier (classifier.py)                               │
│      - Model: indolem/indobert-base-uncased (pre-trained Bahasa Indonesia)  │
│      - Fine-tuned dengan 5000 SMS sintetik Indonesia                        │
│      - Output: probabilitas {benign, smishing}                              │
│      - Fallback: rule-based jika model belum di-fine-tune                   │
│                                                                             │
│   C. Urgency Scorer (urgency_scorer.py)                                     │
│      - Scoring 0-100 berdasarkan kata kunci:                                │
│        URGENT_WORDS  : segera, sekarang, hari ini, cepat (+15/kata)         │
│        THREAT_WORDS  : diblokir, dibekukan, ditutup, sanksi (+20/kata)      │
│        REWARD_WORDS  : menang, hadiah, gratis, bonus, voucher (+12/kata)    │
│        ACTION_WORDS  : klik, verifikasi, transfer, kirim (+8/kata)          │
│        CAPS BONUS    : jika > 30% huruf kapital (+20 poin)                  │
│      - Score ≥ 70: SANGAT MENCURIGAKAN                                      │
│      - Score 40-69: ELEVATED                                                │
│                                                                             │
│   D. Sender Number Reputation (number_reputation.py)                       │
│      - Cek nomor pengirim terhadap blocklist                                │
│      - Deteksi pola: nomor internasional (+44, +1, dst → curigai)           │
│      - Deteksi: short code mencurigakan                                     │
│      - Blocklist: database nomor yang dilaporkan sebagai scammer            │
│                                                                             │
│   FORMULA SKOR (Weighted Aggregate):                                        │
│     Score = (IndoBERT × 0.45) + (Urgency × 0.25) +                        │
│             (URL Risk × 0.15) + (Number Rep × 0.15)                        │
│     ≥ 0.60 → MALICIOUS | 0.30–0.59 → SUSPICIOUS | < 0.30 → SAFE           │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ MODULE 3: VISHING DETECTOR (PHASE 2 — STUB)                                 │
├─────────────────────────────────────────────────────────────────────────────┤

ALUR DATA DETAIL:

  [Web Classification]
  Input: URL string
    → Normalize URL
    → Cache lookup (hash MD5, TTL 1 jam)
    → Extract 25 fitur lexical
    → Predict (RF+XGB ensemble ATAU rule-based jika model belum ada)
    → Brand typosquat check (Levenshtein vs 123 brand aliases)
    → SSL certificate check (timeout 3 detik)
    → Weighted aggregate → label + confidence + reasons
    → Simpan ke SQLite + cache
    → Return JSON response

  [SMS Classification]
  Input: {text, sender_number, timestamp}
    → Preprocess text (normalisasi, ekstrak URL/nominal)
    → Ekstrak URL → kirim ke Web Module untuk tiap URL
    → IndoBERT classify (atau rule-based fallback)
    → Compute urgency score (keyword rules)
    → Check sender number reputation
    → Weighted aggregate → label + confidence + urgency + urls_found
    → Simpan ke SQLite
    → Return JSON response

BAGIAN 4 — CARA INSTALASI
================================================================================

PERSYARATAN:
  - Python 3.10 atau lebih baru
  - pip (package manager)
  - Minimal 4 GB RAM (untuk IndoBERT)
  - Koneksi internet (untuk download IndoBERT dari HuggingFace pertama kali)
  - GPU (opsional, untuk training lebih cepat)

LANGKAH 1 — Clone / Download Project
  Jika menggunakan git:
    git clone <url-repo> tridetect
    cd tridetect

  Jika download manual:
    Extract zip ke folder kerja, masuk ke folder tersebut.

LANGKAH 2 — Install Dependencies

  CARA A (recommended, install sebagai package):
    pip install -e .

  CARA B (install dependencies satu per satu jika A gagal):
    pip install fastapi uvicorn pydantic
    pip install scikit-learn xgboost pandas numpy
    pip install tldextract python-Levenshtein
    pip install transformers torch
    pip install click rich streamlit
    pip install httpx aiofiles joblib

  Untuk Vishing (Phase 2, opsional):
    pip install openai-whisper soundfile librosa

LANGKAH 3 — Generate Data Training
  python scripts/generate_synthetic_sms.py

  Output: tridetect/data/sms_synthetic.csv
  - 2500 SMS phishing sintetik (bahasa Indonesia)
  - 2500 SMS normal/benign sintetik

LANGKAH 4 — Validasi Brand Database
  python scripts/seed_brands.py

  Output: Daftar 33 brand dengan total 123 alias yang dimuat.

LANGKAH 5 — (Opsional) Training Model ML

  Web Phishing Classifier:
    python scripts/train_web.py
    → Simpan: models_pretrained/web_rf/rf_model.pkl
    → Simpan: models_pretrained/web_rf/xgb_model.pkl

  Smishing IndoBERT Fine-tune (butuh 30+ menit, lebih cepat dengan GPU):
    tridetect train smishing --epochs 3
    → Simpan: models_pretrained/smishing_indobert/

  CATATAN: Tanpa training, sistem otomatis pakai rule-based fallback
  yang sudah cukup baik untuk demo dan testing.

LANGKAH 6 — Jalankan Server API
  tridetect serve --port 8000

  Atau langsung dengan uvicorn:
    uvicorn tridetect.gateway.main:app --host 0.0.0.0 --port 8000

  Server aktif di: http://localhost:8000
  API Docs (Swagger): http://localhost:8000/docs
  API Docs (ReDoc): http://localhost:8000/redoc

LANGKAH 7 — Jalankan Dashboard (tab baru / terminal baru)
  tridetect dashboard

  Dashboard aktif di: http://localhost:8501

BAGIAN 6 — CARA MEMBACA OUTPUT / HASIL DETEKSI
================================================================================

LABEL HASIL:

  safe        → URL/SMS aman, tidak terindikasi phishing
                Tindakan: Tidak perlu khawatir, bisa dilanjutkan

  suspicious  → Mencurigakan, perlu verifikasi lebih lanjut
                Tindakan: Jangan klik link, verifikasi ke sumber resmi brand

  malicious   → Sangat berbahaya, dipastikan atau sangat kemungkinan phishing
                Tindakan: Blokir URL/nomor ini, laporkan ke pihak berwajib

CONFIDENCE (Tingkat Keyakinan):
  0.0 - 0.27   → Safe
  0.28 - 0.54  → Suspicious
  0.55 - 1.0   → Malicious

  Semakin tinggi confidence → semakin yakin sistem dengan labelnya
  Contoh: confidence 0.85 malicious = SANGAT YAKIN phishing

URGENCY SCORE (khusus SMS):
  0  - 20   → Tidak ada urgensi mencurigakan (normal)
  21 - 40   → Sedikit urgensi (masih bisa normal)
  41 - 70   → Elevated urgency (perlu waspada)
  71 - 100  → Sangat mendesak (pola phishing klasik)

REASONS (Alasan Deteksi):
  Setiap response berisi array "reasons" yang menjelaskan MENGAPA
  sistem menilai URL/SMS tersebut berbahaya. Contoh alasan:

  Web:
    - "Typosquat of brand 'BCA': 'bcaa' ~= 'bca' (edit distance 1)"
    - "Suspicious free TLD (often abused by phishers)"
    - "IP address used instead of domain name"
    - "URL shortener detected (hides destination)"
    - "SSL: Certificate very new (15 days old)"

  SMS:
    - "Very high urgency score (85/100) — high-pressure language detected"
    - "Contains 2 URL(s): bit.ly/xxx, g0pay.tk/check"
    - "Excessive uppercase usage (78% of letters)"
    - "Monetary amounts detected: Rp 50.000.000"
    - "Sender number +447700900000 is international (suspicious for Indonesian banking SMS)"

BAGIAN 7 — CARA TRAINING MODEL (OPSIONAL, UNTUK AKURASI LEBIH BAIK)
================================================================================

TRAINING WEB PHISHING CLASSIFIER:

  1. Jalankan script training:
     python scripts/train_web.py

  2. Yang terjadi:
     - Generate 4000 URL sintetik (2000 phishing, 2000 benign)
     - Ekstrak 25 fitur per URL
     - Train Random Forest (100 estimators)
     - Train XGBoost (100 estimators)
     - Evaluasi dengan classification report
     - Simpan model ke models_pretrained/web_rf/

  3. Setelah training, classifier otomatis load model yang sudah dilatih.

TRAINING SMISHING CLASSIFIER (IndoBERT Fine-tune):

  1. Pastikan sms_synthetic.csv sudah ada:
     python scripts/generate_synthetic_sms.py

  2. Jalankan fine-tuning:
     tridetect train smishing --epochs 3 --batch-size 16

     Atau langsung:
     python scripts/train_smishing.py --epochs 3

  3. Perkiraan waktu:
     - CPU saja          : 2-4 jam per epoch
     - GPU (CUDA)        : 5-15 menit per epoch
     - Total 3 epochs GPU: ~30-45 menit

  4. Model tersimpan di: models_pretrained/smishing_indobert/
     Saat server restart, model ini otomatis diload.

CATATAN TANPA TRAINING:
  - Web module: menggunakan rule-based scoring (25+ fitur heuristik)
    Sudah cukup baik untuk deteksi pola umum phishing
  - SMS module: menggunakan rule-based keyword matching
    + IndoBERT base (tanpa fine-tune, akurasi lebih rendah)

BAGIAN 10 — TROUBLESHOOTING (PENANGANAN MASALAH)
================================================================================

MASALAH 1: "ModuleNotFoundError: No module named 'tldextract'"
SOLUSI   : pip install tldextract python-Levenshtein transformers torch

MASALAH 2: IndoBERT loading sangat lambat
SOLUSI   : Normal di CPU, bisa 20-30 detik pertama kali.
           Setelah load pertama, sudah ter-cache di memory.
           Jika butuh lebih cepat, pakai GPU atau gunakan rule-based saja.

MASALAH 3: "No connection could be made" saat test API
SOLUSI   : Tunggu server benar-benar aktif dulu.
           Cek log server: ada pesan "Application startup complete"
           IndoBERT perlu waktu ~20 detik untuk load.

MASALAH 4: UnicodeEncodeError di Windows
SOLUSI   : Jalankan python dengan encoding UTF-8:
           set PYTHONIOENCODING=utf-8
           python script_anda.py

           Atau tambahkan di awal script:
           import sys; sys.stdout.reconfigure(encoding='utf-8')

MASALAH 5: "Cannot import 'setuptools.backends.legacy'"
SOLUSI   : Sudah diperbaiki di pyproject.toml.
           Gunakan: build-backend = "setuptools.build_meta"

MASALAH 6: Conflict FastAPI vs Streamlit (starlette version)
SOLUSI   : Gunakan FastAPI >= 0.115:
           pip install "fastapi>=0.115"

MASALAH 7: Model tidak akurat (banyak false positive/negative)
SOLUSI   : Lakukan fine-tuning dengan data nyata:
           1. Kumpulkan SMS phishing Indonesia yang real
           2. Tambahkan ke format CSV (text, label, source)
           3. Jalankan: tridetect train smishing --epochs 5
           4. Restart server

MASALAH 8: Port 8000 sudah dipakai
SOLUSI   : tridetect serve --port 8001
           Atau ganti port sesuai kebutuhan.

BAGIAN 12 — FORMAT API LENGKAP
================================================================================

BASE URL  : http://localhost:8000
API DOCS  : http://localhost:8000/docs     (Swagger UI interaktif)
REDOC     : http://localhost:8000/redoc    (Documentation alternatif)

ENDPOINTS:

  GET  /                          → Info dasar API
  GET  /health                    → Status semua module
  GET  /docs                      → Swagger UI (bisa test langsung di browser)
  POST /v1/classify/web           → Klasifikasi URL
  POST /v1/classify/sms           → Klasifikasi SMS/WhatsApp
  POST /v1/classify/voice         → Klasifikasi voice (501 stub)

REQUEST SCHEMA — Web:
  {
    "url"         : string   (required) — URL yang akan diklasifikasi
    "check_ssl"   : boolean  (default: true) — Cek SSL certificate
    "check_brand" : boolean  (default: true) — Cek brand typosquat
  }

REQUEST SCHEMA — SMS:
  {
    "text"           : string   (required, 5-2000 char) — Teks SMS
    "sender_number"  : string   (optional) — Nomor pengirim (+62...)
    "timestamp"      : datetime (optional) — Waktu SMS diterima
  }

RESPONSE SCHEMA (semua module):
  {
    "label"      : "safe" | "suspicious" | "malicious"
    "confidence" : float (0.0 - 1.0)
    "reasons"    : array of string
    "module"     : "web" | "sms" | "voice"
    "latency_ms" : integer (waktu proses dalam milidetik)

    // Web-specific:
    "brand_match" : string | null (nama brand yang di-typosquat)
    "ssl_valid"   : boolean | null

    // SMS-specific:
    "urls_found"       : array of string
    "urgency_score"    : integer (0-100)
    "sender_reputation": string
  }

BAGIAN 14 — CATATAN ETIS
================================================================================

1. PENGGUNAAN DATASET
   - Semua data training adalah SINTETIK — tidak menggunakan data SMS pengguna nyata
   - Data tidak dikumpulkan dari pengguna tanpa izin
   - Blocklist nomor telepon bersumber dari laporan komunitas publik

2. FALSE POSITIVE
   - Promo agresif dari brand legitimate mungkin terdeteksi sebagai "suspicious"
   - Selalu verifikasi ke sumber resmi jika ragu dengan hasilnya
   - Tidak boleh digunakan sebagai satu-satunya dasar tindakan blokir

3. PRIVASI
   - Input SMS tidak disimpan dalam bentuk teks biasa di database
   - Hanya hash fingerprint (MD5) yang disimpan untuk deduplication
   - Tidak ada logging konten pribadi

4. KEAMANAN
   - Tool ini HANYA untuk tujuan defensif dan penelitian keamanan siber
   - Dilarang digunakan untuk tujuan ofensif atau menyerang sistem pihak lain
   - Digunakan dalam konteks: penelitian akademik, lab keamanan, SOC team

5. DISCLAIMER
   - Akurasi sistem bergantung pada kualitas data training
   - Tidak ada sistem yang 100% akurat — selalu gunakan penilaian manusia
   - Developer tidak bertanggung jawab atas kerugian akibat false positive/negative
